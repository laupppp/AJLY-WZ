# 共享试用版：一台 Windows 电脑 + 门店远程访问

> 目标：不申请公司服务器、不买公司域名、不装数据库软件，让分散在外的门店、总部、供应商
> 打开同一个地址，看到**同一份**订单数据。
>
> 适用范围：**内部试点 / 流程验证**。正式上线仍需备案域名、企业微信免登与异地备份。

---

## 一、这套东西是什么

`server/app.js` 是一个自带的服务端：

- 用 Node.js 内置的 SQLite 存数据，**不用装 MySQL / SQL Server**
- 同时把 `h5/` 的页面直接托管出去，浏览器打开就是完整系统（不是简版）
- 前端所有操作通过 `/api/action` 提交，服务端用**令牌对应的真实身份**重放业务规则，
  权限判定在服务端，前端改不了自己的角色
- 全站只有一份 state，A 下单、B 立刻看得到（默认 4 秒自动同步）

代码与 `server/dev.js` 那条「共享采购测试」互不干扰，两套可以并存。

## 二、门店在外面怎么连（三条路，按推荐顺序）

### 路线 A：组网工具（最稳、真正零资源，推荐给「先跑通试点」）

用 **Tailscale**（或国内节点更友好的 **EasyTier / ZeroTier**）把 Windows 电脑和门店手机
组成一个加密虚拟内网。

- 不需要公网 IP、不需要域名、不需要备案、不把系统暴露到公网
- 免费版一般够小团队用（Tailscale 免费 100 台设备 / 3 用户，无流量上限）
- 门店访问形如 `http://100.x.y.z:3010/`（MagicDNS 可以用设备名）

代价：**每台设备要装一个客户端并登录同一账号**；P2P 打洞失败时会走中继、速度变慢。
适合先把流程跑通、验证「多人共享一份数据」这件事。

### 路线 B：内网穿透 HTTPS 隧道（门店零安装，体验最好）

用花生壳 / Cpolar / natfrp 之类，把 `127.0.0.1:3010` 映射成一个 HTTPS 地址，
门店在企业微信里点链接就能用。

**2026 年的现实限制，务必先看：**

| 项 | 免费版实际情况 |
|---|---|
| 实名认证 | 国内节点**强制实名**，未实名无法启用隧道 |
| 公网 80/443 | 国内节点要求已备案域名；部分服务商的「加密壳域名」自带备案（约 58 元/年） |
| 免费额度 | 常见 1 条隧道 / 1 Mbps / 1 GB 月流量，采购系统带验收照片会偏紧 |
| 域名 | 随机二级域名，删除重建会变；要固定地址需低价付费档（几十元/年起） |

也就是说：**完全不花钱、不实名、不备案，还想门店点链接即用 —— 这条路现在走不通。**
但花几十元/年买一个固定二级域名（个人出资，不占公司资源）是可行的，
且比申请公司服务器、域名、备案流程轻得多。

### 路线 C：临时演示（零成本，但不适合长期）

Cloudflare Tunnel 的 Quick Tunnel：不用账号、不用实名、不用域名，
一条命令给一个 `https://xxx.trycloudflare.com` 地址并自动 HTTPS。
**但地址约 24 小时就会变**，国内晚高峰偏慢，还有机器人校验。
只适合「今天给领导演示一下」，不适合发给门店天天用。

### frp 自建

需要一台有公网 IP 的服务器 —— 如果自己买一台低价 VPS 也可以，
但那就属于「自己搭中转」而不是「不占资源」了，故不列为首选。

> 补充：**只是把链接发在企业微信里让门店点开，一般不需要配「可信域名」。**
> 只有做企业微信免登（OAuth 取身份）或调用 JS-SDK 时，才硬性要求 ICP 备案域名。

## 三、Windows 电脑上的部署（一次配置）

1. 安装 **Node.js 26 LTS**（22.5+ 也可，需带 `node:sqlite`）：https://nodejs.org/
2. 把项目拷到这台电脑，例如 `D:\AJLY-WZ`
3. 双击 `server\start-windows.bat`，或在项目根目录运行：

   ```powershell
   npm run shared:start
   ```

4. 浏览器打开 `http://127.0.0.1:3010/` 应能看到系统。
5. 首次启动会在**项目文件夹旁边**生成 `ajly-shared-data\`：

   | 文件 | 作用 |
   |---|---|
   | `shared.sqlite` | 全部业务数据，唯一权威副本 |
   | `credentials.json` | 各身份的访问令牌（保密） |
   | `accounts.txt` | 可直接分发给门店的账号清单（保密） |
   | `shared-backup-*.sqlite` | 每日在线备份 |

   这个目录在仓库之外，不会被 git 提交，也不会被误传到 GitHub。

6. 注册开机自启与每日备份（管理员 PowerShell）：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\server\setup-tasks.ps1
   ```

   会建两个计划任务：登录后 30 秒启动服务、每天 02:00 在线备份。
7. 电源选项改成「从不睡眠」，电脑保持登录状态。

> 服务只监听 `127.0.0.1`，**不需要在 Windows 防火墙放行端口**；
> 对外访问交给穿透 / 组网客户端转发，攻击面更小。

## 四、把账号发给门店

打开 `ajly-shared-data\accounts.txt`，把**每人的姓名 + token 单独发给他**，不要发到群里。

两种进入方式：

- 打开系统地址 → 粘贴 token → 进入（身份由服务端决定，进去后不能自行切角色）
- 或者直接发一次性链接：`https://<你的地址>/?token=<他的token>#/home`（点开自动登录），
  提醒对方不要转发链接

当前共 9 个演示身份：2 位店长、2 位战区负责人、中台、职能部门、3 家供应商。
正式使用前需换成真实人员与真实门店归属。

## 五、日常维护

| 事情 | 怎么做 |
|---|---|
| 看状态 | 访问 `/api/health`，返回 `{"ok":true,"revision":N}` |
| 手动备份 | `npm run shared:backup`（校验完整性后生成备份文件） |
| 换电脑 / 迁移 | 整个 `ajly-shared-data\` 目录拷过去即可 |
| 清空重来 | 停服务 → 删 `shared.sqlite` → 重启（令牌会重新生成） |
| 保留演示数据 | 设环境变量 `AJLY_KEEP_DEMO=1` 再启动，否则新库是空的 |

每周把 `shared-backup-*.sqlite` 拷一份到 U 盘或网盘 —— 目前**只有本机备份**，硬盘坏了就没了。

## 六、必须说清的风险（向领导汇报用大白话）

1. **这是试点，不是生产系统。** 电脑断电、休眠、重启，系统就断；没有监控、没有异地备份、没有 UPS。
2. **令牌是固定测试值**，不是员工正式账号；拿到令牌的人就能以该身份操作系统，务必一人一令牌。
3. **真实业务数据走公网要审批。** 路线 B 的流量经过第三方服务商节点，采购金额、供应商、门店信息对外可见，
   上线前请过公司信息安全。路线 A（组网）不暴露公网，风险最小。
4. **演示数据不能直接用。** 社区活动单价是预算指导价、合同额度 `HT-DEMO-ACTIVITY` 是虚构值，
   正式下单前必须替换成中标合同价与真实合同。
5. **企微免登仍未接。** 现在靠发令牌，不能自动识别是谁；要免登就得备案域名 + 自建应用可信域名，
   那一步绕不开公司资源。
